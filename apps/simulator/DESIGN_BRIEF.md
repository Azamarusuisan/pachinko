# DESIGN_BRIEF — Pachinko Playfield, Lottery Motion & Smoothness Harness
承認: ユーザー / 2026-08-10 / 版: v2.1

## 1. 主題
- 対象: 既存パチンコシミュレーターの図柄変動・リーチ・結果演出と、その滑らかさを測る開発用ハーネス
- 読者: 実機に近い挙動を確認するプレイヤー兼開発者。まずMac miniのデスクトップChrome、既存モバイル表示も壊さない
- 唯一の仕事: 玉が実在する遊技領域を通り、その奥のLCDでSTART後の演出が意味的に正しく滑らかに進む状態を作る
- 成功指標: 見える釘と物理Colliderが1対1で一致し、中央LCD表示面へ散在釘や通常流路の玉が侵入しない。`左停止 → 右が同図柄で停止（リーチ成立） → 中央だけ回転 → 結果停止` も自動検証できる

## 2. 審査
- 最終判断者: ユーザー
- 過去のNG: 「リーチ」の表示なのに左右図柄が揃わない状態、背景画像の装飾釘と物理釘の二重表示、LCD内へ釘と玉が浮く状態
- 過去のOK: 777Real系の、盤面遊技を続けながら液晶演出が段階的に進む見せ方
- 経由するレビュー: ユーザー直接

## 3. 世界観
- 題材の固有物: 図柄帯、変動、テンパイ、リーチ、停止順、保留、液晶、効果音
- ブランド人格: 実機の演出制御卓。派手さより停止順と間を正確にする
- 参照: 777Real公式ページ — 実機アプリとして盤面と液晶演出を同時に見せる構成
- 反面教師: 静止画を「回転」と呼ぶ、結果だけ差し替える、計測できない雰囲気アニメーション
- 業界の型: 抽選結果は先に確定し、表示は独立した時系列で `変動 → テンパイ → リーチ → 結果` を見せる型を踏襲する

## 4. トークン
### Color
- 保留は既存LED色の青・緑・赤・虹。期待度は `青 < 緑 < 赤 < 虹` とし、字幕色・発光・読み上げ用テキストも同じ抽選結果を参照する

### Type
- Display / Body / Data: 既存指定を維持する
- 和欧混植: 既存フォールバックとウェイトを変更しない

### Layout
- コンセプト: プレイヤー画面は増築せず、動画・図柄・字幕を筐体の液晶開口部へ埋め込む。釘と玉はLCDを除外した遊技領域だけへ表示し、計測UIは通常画面から分離した開発用ハーネスに置く
- 盤面素材: 筐体下地には釘を焼き込まない。暗い矩形やmaskを上から被せて消したように見せず、釘なし下地の上へColliderと1対1の物理釘だけを描く
- 密度: 既存のまま
- ワイヤー:
  ```text
  通常画面: [筐体背面] < [LCD: 動画 + 図柄] < [LCDを除外した物理玉/釘] < [中央役物・透明樹脂] < [ガラス]
  開発用:   [同じ液晶] [timeline / frame interval / dropped frames / long tasks / pass-fail]
  ```

### Signature
- 左右が同図柄で止まった瞬間にリーチが成立し、中央だけが流れ続ける明快な停止順

### Motion
- 予算: 一点豪華。液晶の図柄変動と物語映像だけを優先する
- 主演: 図柄帯をコンポジタ向きの `transform` で連続移動し、停止時だけ減速させる
- 助演: 物語映像はJPEGのReact差し替えをやめ、動画再生または事前デコード済み素材へ一本化する
- 合成: 動画・図柄・字幕はLCD専用面へ置き、物理釘はその領域から除外する。外向きの発光枠を使わず、内側の暗さでガラス越しに見せる
- 奥行き: `盤面背景 → LCD → LCD外の物理玉・釘 → 中央役物・透明樹脂 → ガラス` とする。LCD表示面はno-nail領域とし、玉を見せる場合はワープ先の専用ステージ形状に限定する
- 光量: 動画は液晶奥を維持しつつ、変動中は筐体四辺のLED反射・図柄発光・字幕発光を最大化する。中央映像の白飛びではなく外周から光を漏らす
- 赤文字: 一部の変動を抽選結果とは独立したチャンスアップにし、赤い「激熱」が液晶面から手前へせり出して停止する。大当り確定表示にはしない
- 保留: 入賞時に固定seedから色を決め、消化まで保持する。色は結果を後から変更せず、低期待度色でも当たり得る
- 虹大当り: 参考画像の白熱した虹・宝石・祝福感を、固有キャラクターや既存ロゴを複製しないオリジナル背景で再構成し、777と結果文字は動的レイヤーとして重ねる
- 勝負文字: 太く圧縮した和文に白ハイライト、虹または灼熱グラデ、濃い縁、金属押し出し影を重ね、画像化せず状態と同期してスラムインさせる
- 同期: 複数の `setTimeout` ではなく単一の単調増加タイムラインをSource of Truthにする
- reduced motion: 回転を短いクロスフェード＋即時停止へ縮退する

## 5. コピー
- トーン: 実機用語を短く使う（変動中、リーチ、結果）
- 禁止語: 状態が成立していないのに「リーチ」と表示すること
- 確定原稿: 既存原稿を維持

## 6. 禁止事項
- 左右不一致のままREACHへ遷移しない
- 中央図柄の静止状態を「回転中」と扱わない
- 60fpsを名乗りながら同一画像を複製しただけの素材を合格にしない
- 通常プレイ画面へ常設の性能パネルを追加しない
- 物理結果や大当たり確率を演出側から変更しない
- 背景画像へ焼き込んだ釘を当たり判定のある釘として見せない
- 左通常ルートと右打ちルートを鏡写しの同一ゲージにしない
- Collider軸径と表示用釘頭径を同一値として扱わない

## 7. 技術制約
- スタック: React 19 / PixiJS 8 / Rapier 2D / Vite。新規依存は追加しない
- 対応幅: 既存320px以上を維持
- a11y: `prefers-reduced-motion`、意味のある状態テキスト、色だけに依存しない
- Harness: 画面を一切追加せず、固定seedと固定シナリオを裏で自動実行する。状態順序、phase timing skew、rAF frame interval（median/p95/max）、50ms以上のlong task、動画のpresented/dropped frames、物理step時間をlocalStorageとwindow上へJSON保存する
- 合格基準: 意味テストは必須。性能値は端末・refresh rate別に記録し、初回は恣意的な固定FPSではなくbaseline比較で判定する
