# v2 → v2.1 START Regression Analysis

## Provenance limit

The repository does not contain the v2 board JSON. Its first available commit already contains
`2.1.0-right-play-rebuild`; there are no tags, branches, or earlier board blobs for v2. Therefore an
exact coordinate/material diff is not recoverable from Git. The v2 numbers below are recorded
results, not a rerun. This missing immutable input is itself a reproducibility defect and is why
versioned experiment hashes and saved results are now required.

## Recorded comparison

Both recorded runs use seed `123456`, strength `0.68`, 100 balls/min, 240 Hz, and CCD enabled.

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| v2 (`2.0.0-research-rebuild`) | 10,000 | 464 | 7,536 | 2,000 | 4.64% | 1.5313 s | 19.410 | 27.72% | 12.76% | 59.52% |
| v2.1 (`2.1.0-right-play-rebuild`) | 10,000 | 3,446 | 5,725 | 829 | 34.46% | not recorded | 19.8526 | 88.55% | 1.09% | 10.36% |

Documented v2.1 changes are a shared-launcher physical split, a fixed upper return,
an `UPWARD_ONLY` inner-launch gate with per-ball collision groups, and dedicated right-play
sensors. Exact old nail, rail, launcher, and sensor coordinates are unavailable.

## Confirmed findings

1. The one-way launch gate is a major contributor: removing it lowers START by 15.0 percentage
   points and changes the first-route distribution from 88.1% left to 47.2% left.
2. The fixed upper return is not the primary cause. Removing it increases START slightly.
3. Right terminal sensors and right-route nails change terminal mix by only a few percentage points;
   neither explains the 31.7-point v2→v2.1 jump.
4. Launcher behavior is discontinuously sensitive. With the gate removed, changing only angle
   `-94° → -98°` lowers START `21.3% → 6.4%`; changing only strength `0.68 → 0.50` lowers it
   `21.3% → 4.3%`. Launch X changes of 6 mm also move START by double-digit points.
5. Current START detection is a 1 mm-wide sensor intersecting an 11 mm ball, giving an effective
   horizontal capture span near 12 mm. This is current geometry, not proof of v2 geometry.

## Not proven

- The exact remaining cause cannot be assigned among launcher position/angle/velocity, launch rail
  geometry, and any lost nail/sensor coordinate changes without the original v2 JSON.
- The recorded v2 and v2.1 route percentages may use different route sensor geometry, so they are
  not pure trajectory measurements.
- Neither 4.64% nor 34.46% is an observed real-machine target.

## Heatmap evidence

Two 25 mm-grid experiments were saved with immutable hashes:

| Variant | Config hash | Board hash |

| no launch-inner gate / 1,000 balls | `67e3e979a4bf4edd0ee5dca4ee9baac7d8ce89944d89116828329fe3ce3154b2` | `986e41ec2291638f38293a920c3dbad83d4d3d39e9db59cb86e6fddab20d8b26` |

The current gate keeps the rising ball on the outer side of the launch lane: cells at x=450 mm,
y=100–175 mm gain roughly one passage per ball, while no-gate runs move those passages to x=425 mm.
The largest collision increases then appear at x=300–350/y=125 (upper return/central entry) and
x=225–275/y=400 (lower START approach). This establishes a causal route:

```text
UPWARD_ONLY gate alignment
→ repeatable outer-lane ascent
→ upper return / central-field entry
→ more traffic and collisions in the lower START approach
→ higher START count
```

The current 1,000-ball run observed average speed `0.5356 m/s`, maximum speed `3.4949 m/s`,
average collision speed before/after `0.9462/0.6414 m/s`, and zero clamp activations. No abnormal
acceleration was observed under this fixed scenario. This does not prove safety for every config.

## 2.2 integrity addendum

Later solver-isolation tests showed that the former 36.3% baseline was also under-resolved. With
the same 2.1 geometry, changing only the effective solver step from 1/240 s to 1/480 s changed the
1,000-ball START rate from 35.5% to 17.7%. With the corrected `n070` clearance, the same comparison
was 27.2% versus 15.0%. The solver step is therefore a confirmed major cause of the apparent rate
change; it is not evidence that either rate matches a real machine.

At 1/480 s, the old geometry exposed a deterministic stationary trap near `(205, 310) mm`. The
free gap between `n070` and the display rail was 8.291 mm, smaller than the 11 mm ball. Moving only
`n070` from y=305 mm to y=301 mm increased that gap to 12.048 mm and removed the reproduced trap.
This change is a clearance correction, not a START-rate target adjustment.
